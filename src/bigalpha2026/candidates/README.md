# Candidate 目录约定

基础候选只分为四类：

| 目录 | 含义 | 典型数据 |
|---|---|---|
| `pv/` | 价量因子 | 日线或分钟聚合后的价格、成交量、成交额 |
| `hf/` | 分钟成交因子 | 分钟收益、成交笔数、冲击与恢复路径 |
| `ob/` | 盘口因子 | 五档报价、价差、深度、盘口恢复 |
| `fr/` | 财务因子 | 严格 PIT 对齐后的财务披露 |

`composite/` 不是第五类基础因子。它只放已经冻结实现的跨类组合或模型因子：

- `INT-001` 的数据来源为 `FR + HF`；
- `MICRO-EN-001` 的数据来源为 `HF + OB`，当前仍是
  `development_watch`，训练和推理合同冻结前不创建实现文件。

## 队友新增候选

1. 先在 `docs/candidate_registry.md` 登记候选编号、经济机制、方向、数据列和
   预期持有期。
2. 在对应目录中新增小写文件，例如 `hf/hf_003.py`。
3. 输出必须是 `date、instrument、factor`，且因子值越大代表预期收益越高。
4. 在对应的 `__init__.py` 导出公开函数，并在 `tests/` 增加同编号测试。
5. 不允许看过结果后原地翻转方向；相反机制使用新编号和未查看区间验证。
6. 跨类因子在各基础组件通过评价后才能进入 `composite/`。
