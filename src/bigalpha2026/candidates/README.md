# Candidate 目录约定

基础候选只分为四类：

| 目录 | 含义 | 典型数据 |
|---|---|---|
| `pv/` | 价量因子 | 日线或分钟聚合后的价格、成交量、成交额 |
| `hf/` | 分钟成交因子 | 分钟收益、成交笔数、冲击与恢复路径 |
| `ob/` | 盘口因子 | 五档报价、价差、深度、盘口恢复 |
| `fr/` | 财务因子 | 严格 PIT 对齐后的财务披露 |

`composite/` 不是第五类基础数据。它用于跨类组合或模型候选，例如
`FR + HF`、`HF + OB`。

未冻结、没有明确训练动作的 `watch` 候选不放入目录。

OAP A/B级26个候选的编号、忠实度、窗口、方向和S/I结果见
[`OAP_CANDIDATES.md`](OAP_CANDIDATES.md)。该表与
`docs/candidate_registry.md` 一起维护：前者面向实现，后者面向全项目状态。

## 队友新增候选

1. PR 默认只新增自己认领的候选文件，例如 `hf/hf_003.py`。
2. 输出必须是 `date、instrument、factor`，且因子值越大代表预期收益越高。
3. 不要在候选 PR 中修改 registry、`__init__.py`、评价脚本或组合训练脚本；这些
   由主仓库负责人统一接入，减少冲突。
4. 如果依赖当前数据包没有的新字段，需要交付 GitHub Release asset：
   Feather/Parquet 数据包、SHA-256、字段清单、覆盖年份和生成说明。
5. 不允许看过结果后原地翻转方向；相反机制使用新编号和未查看区间验证。
