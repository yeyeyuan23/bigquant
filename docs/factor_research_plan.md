# BigAlpha 2026 因子选择与评估执行计划

## 1. 目标与边界

本计划指导从数据核验、候选生成、单因子评价、组合评价到比赛提交的完整流程。

固定边界：

- 原始分钟成交、盘口快照和未经筛选的财务原表只在 BigQuant AIStudio 内使用；通过平台工具按数据族聚合后的股票日研究面板可在下载配额和数据协议范围内一次性保存为本地 Parquet。
- 所有候选最终生成日频的 `date、instrument、factor` 三列结果。
- 因子值越大代表预期下一期收益越高。
- 研究以历史时点可见信息为准，禁止未来数据泄漏。
- 公榜只验证已经通过 AIStudio 历史研究门槛的候选，不作为主要搜索工具。
- 当前仓库不预设任何具体候选公式，候选必须按本计划重新建立。

### 1.1 执行环境边界

| 环境 | 允许执行 | 不允许作为结论 |
|---|---|---|
| 本机 `conda quant` | 因子池、候选定义、评价门槛和组合规则的唯一事实来源；读取经 AIStudio 聚合并通过官方 UI 下载的日频 Parquet；生成因子、历史 IC、分组、组合、消融和冻结记录 | 扫描比赛原始分钟、盘口或财务全表；改写已经看过区间的因子方向和门槛 |
| 网页 AIStudio | DAI 查询、字段核验、PIT 和异常处理核验；按一级数据类别将原始数据一次聚合为股票日研究面板；核对行数、覆盖率和落盘结果 | 临时定义因子、评价门槛或组合权重；为每个候选重复扫描同一原始表 |
| 比赛网页 | 上传 Notebook、查看官方评分、排名及候选状态 | 因子研发和参数搜索 |

本机 Python 命令必须显式使用 `conda run --no-capture-output -n quant python`，不得使用系统 `/usr/bin/python3`。AIStudio 负责真实数据生成和数据族验收，本地负责可复现的因子评价与组合；上传前必须能从固定 Parquet 和本地版本化规则重建全部结果。

## 2. 因子分类体系

采用“数据族 + 机制标签”的分类：

- 基础数据族只保留四类，直接决定数据合同、取数方式、异常处理和共享验收：`FR` 财务披露、`PV` 日频量价、`HF` 分钟成交、`OB` 分钟盘口。
- 经济机制单独登记，例如质量改善、价格吸收、反转、冲击恢复、成交效率或盘口韧性，用于判断候选是否重复以及后续组合是否有增量。
- 数据来源允许多值。使用两个以上数据族的候选登记为交互或组合候选，并列出 `data_sources: [FR, HF]` 等元数据，不再建立 `XS` 基础类别。

每个基础候选在开发前必须登记一个主数据族、经济机制、信息来源、可用时点和预测周期。交互候选登记多个数据族及其输入角色，只能在基础因子完成正式单因子评价后进入组合阶段。数据族相同不代表经济机制相同；机制相近但数据源不同也必须在相关性和消融阶段复核。

### 2.1 低频基本面

研究范围：盈利能力、盈利质量、成长及变化、估值、资产负债结构、现金流、财务异常、公告和预期变化。

约束：

- 按实际披露日期做 PIT 合并；
- 明确流量项目、存量项目和报告期口径；
- 不允许用报告期结束日代替披露日；
- 同时评价原始信号和风险中性化后的剩余信息。

### 2.2 日频量价

研究范围：收益路径、趋势与反转、波动与振幅、成交量、成交额、换手、流动性、量价关系、横截面和时序状态。

约束：

- 明确信号是在开盘前、盘中还是收盘后可得；
- 滚动计算只能使用当日及以前的数据；
- 必须评价换手率和信号衰减。

### 2.3 高频成交

研究范围：日内成交方向和不平衡、成交规模结构、成交集中度、价格冲击与恢复、日内时段结构、高频波动和流动性状态。

约束：

- 先确认字段是分钟增量还是当日累计；
- 正确处理午休、停牌、跨日重置和数据异常；
- 分钟数据聚合为日频后再进入统一评价；
- 记录计算资源和运行时间。

### 2.4 盘口

研究范围：报价价差、各档深度及结构、买卖盘不平衡、报价变化、盘口撤补和恢复、盘口状态与成交价格之间的关系。

约束：

- 核对盘口档位、价格和数量字段定义；
- 不把快照变化直接等同于新增委托或撤单；
- 评价与公开盘口因子的相关性和增量贡献；
- 避免只对同一类表达式做细小参数搜索。

### 2.5 组合、交互与模型输出

本节不是第五个基础数据族，而是基础因子完成评价后的派生层。研究范围包括不同数据族之间的条件关系、多个弱信号的分散组合、状态过滤、非线性交互和机器学习预测值。

约束：

- 每个输入特征必须先通过时点和质量检查；
- 跨源信息由组合规则或显式交互项携带，不为同一输入重复生成原始研究面板；
- 模型训练、验证和测试必须按日期切分；
- 模型输出仍是一列日频因子；
- 复杂模型必须在样本外稳定超过简单基准才允许保留。

## 3. 研究阶段与时间切分

固定使用以下区间：

- 2022 短区间：仅用于端到端冒烟、接口、覆盖率和评价代码核验；已经查看的 2022 全年结果保留为诊断证据，但不得单独决定因子有效、无效、翻转或淘汰；
- 2019—2022：基础因子的正式开发期和跨市场状态评价；
- 2023：冻结候选的首次样本外确认，不允许回看后修改公式、方向、门槛或月份；
- 2024：冻结后的最终历史检验；
- 公榜：提交验证；
- 私榜：冻结候选的样本外评价。

2024 年结果首次读取前，必须冻结数据字段、特征定义、缺失值处理、方向、窗口、参数、组合方式、模型结构和训练方法。读取结果后不得针对该区间继续调整同一候选。

## 4. 第零阶段：平台与数据合同

### 已核验的平台基线

以下结论于 2026-07-25 在网页 AIStudio 用短日期、少量股票和 DAI 侧聚合核验；平台数据版本变化后必须重新执行：

| 数据对象 | 已确认数据表 | 关键合同 |
|---|---|---|
| 历史股票池 | `bigalpha_2026_instruments` | 中国交易日逐日 1000 只；`date、instrument` 唯一；必须作为研究面板左表 |
| 比赛分钟行情及五档盘口 | `bigalpha_2026_stock_bar1m` | 活跃股票每日 240 行，时间为 09:31—15:00，午休无记录；`volume、amount、deal_number` 是分钟增量 |
| 财务 | `bigalpha_2026_financial` | 披露事件表；`date` 是可见日期，`report_date` 是报告期，`category` 包含 `lf、mrq、ttm`，`shift=0` 是当时最新报告期 |
| 风险暴露 | `bigalpha_2026_exposure` | 含风格暴露、一级行业和流通市值；按 `date、instrument` 对齐 |
| 公共日线 | `cn_stock_bar1d` | 可用于独立日线核验；不存在 `bigalpha_2026_stock_bar1d` |
| 中国交易日历 | `all_trading_days` | 使用 `market_code='CN'` 显式确定下一交易日 |

固定连接和时点规则：

- 分钟表包含大量股票池外证券，不能替代比赛股票池；先建立每日 1000 只股票池，再左连接行情、财务和风险数据。
- 池内停牌股票可能整日没有分钟记录。保留股票池行并记录缺失，不得用该股票下一次有交易的日期代替当日。
- 分钟成交量、成交额和成交笔数按日求和，不做差分；OHLC 和盘口字段按各自定义聚合。
- 五档盘口中的零价或零量表示该档无有效报价，不是可参与排序、均价或深度计算的真实零值。盘口特征必须先按“价格和数量均为正”筛选有效档位，并同时输出有效档数；2024-01-02 历史股票池内短窗复核中，双侧至少各一档的覆盖率为 99.757606%，双侧完整五档为 98.917586%。
- 财务披露可能发生在周末。因子日使用 `date <= 因子日` 的 backward as-of 合并，并显式选择 `category` 和 `shift`；不得按 `report_date` 或同日相等连接。
- 财务字段按 `category` 分层使用：短窗核验中 `total_assets` 只在 `lf` 有值，`mrq` 和 `ttm` 不提供该字段。跨口径组合必须明确每个字段的类别及角色，不得因空值而隐式混用。
- 下一期研究标签先由中国交易日历确定 `next_date`，再连接 `next_date` 的收益。禁止按单只股票直接 `shift(-1)`，否则会跨过停牌日，把一期标签变成多日标签。
- 暂定研究标签为下一交易日 `close / pre_close - 1`；官方未明确成交价、成本和可执行调仓时点，因此该标签是研究口径，不等同于完整交易回测。
- DAI 查询必须带日期或证券过滤，优先投影必要字段并在 DAI 侧聚合；禁止用宽表 `SELECT *` 做大范围探测。

### 本地研究数据合同

本地数据按用途分层，不以时间频率作为顶层目录；特征层再按原始数据族分开。固定结构为：

```text
data/
├── universe/                 # 历史股票池、交易状态和日历映射
├── features/
│   ├── PV/                  # 日频量价通用组件
│   ├── HF/                  # 分钟成交聚合后的日频通用组件
│   ├── OB/                  # 分钟盘口聚合后的日频通用组件
│   └── FR/                  # 严格 PIT 的财务状态或披露组件
├── exposures/               # 行业、市值、流动性和其他风险暴露
├── labels/                  # 独立保存的未来收益标签
└── factors/                 # 本地候选及组合输出
```

固定规则：

- `features` 只能包含因子日在对应 `available_time` 前可见的信息，禁止混入 `next_*` 或未来收益列；`labels` 在评价时才连接。
- `features` 保存可供同族多个候选复用的通用中间组件，不保存 `hf001_raw、ob002_raw` 等与单个候选编号绑定的列。
- `universe、features、exposures、labels` 的日频主键为 `date、instrument`；`factors` 使用长表，主键为 `date、instrument、candidate_id、factor_version`。
- 数据集按数据族和年份分区；只有单个分区仍过大时才继续按月分区，禁止生成每日小文件。
- 每个数据集记录 `panel_frequency、source_frequency、available_time、date_role、schema_version、generated_at`。频率是数据合同元数据，不作为顶层目录。
- `PV、HF、OB` 的本地正式研究面板均为日频；分钟原始数据留在 AIStudio。`FR` 可以保留披露事件或 PIT 日状态，但必须明确 `disclosure_date、effective_date、report_date` 的角色。
- 因子输出与组合输出不属于共享特征面板。长表中同一 `date、instrument` 出现多个候选不是重复；只有完整主键重复才是错误。
- 旧版 `minimal_research_mart_2022q1.parquet` 和 `pv_research_mart_2022.parquet` 因混合特征、标签及候选专用中间量，已在重新执行 Step 0 时删除，不得作为 2019—2022 正式数据模板。

### 操作步骤

1. 在 AIStudio 用日期过滤、单股和必要字段做最小查询。
2. 核对股票池、日线、分钟、盘口、财务、风险暴露和中国交易日历。
3. 记录每张表的字段、类型、更新频率、可用时点和唯一键。
4. 先验证股票池每日数量、交易日历一致性、重复键和代码格式。
5. 将分钟表与股票池对照，区分池外证券、停牌缺失和代码映射异常。
6. 核对分钟增量口径、240 分钟边界、午休、跨日、OHLC 和盘口异常。
7. 核对财务可见日、报告期、`category`、各类别字段覆盖、`shift`、周末披露和重复键。
8. 核对风险暴露的日期、行业字段和风格字段。
9. 用显式下一交易日映射生成短窗收益标签，并检查停牌日不被跳过。
10. 记录查询耗时；宽表或响应慢的查询改为字段投影和 DAI 侧聚合。

### 阶段产物

- 数据合同；
- 本地研究数据目录、主键、分区和元数据合同；
- 字段核验结果；
- PIT 规则；
- 股票池规则；
- 收益标签定义；
- 停牌、缺行情和代码映射异常规则；
- 最小查询运行日志。

### 通过条件

- 所有必要表和字段均已确认；
- 数据时点不存在歧义；
- 股票池、交易日历和各数据表的连接方向已固定；
- 特征、标签、风险暴露和因子输出已经物理隔离；
- 停牌时的特征和标签缺失处理已固定；
- 最小查询可以稳定复现；
- 未通过前不得开始大规模候选计算。

## 5. 第一阶段：候选登记

每个候选先登记，后实现。登记表至少包含：

| 字段 | 内容 |
|---|---|
| `candidate_id` | 唯一编号 |
| `data_family` | 主数据族：`FR、PV、HF、OB` |
| `data_sources` | 实际使用的数据族列表；基础候选通常为单值，交互候选允许多值 |
| `mechanism` | 经济机制标签 |
| `hypothesis` | 经济或市场机制 |
| `source_tables` | 使用的数据表 |
| `available_time` | 最早可用时点 |
| `expected_direction` | 预期方向 |
| `expected_horizon` | 预期预测周期 |
| `components` | 组成部分及各自角色 |
| `failure_conditions` | 可能失效的状态 |
| `duplication_risk` | 与常见因子的重复风险 |
| `complexity` | 计算和模型复杂度 |
| `status` | 当前研究状态 |

候选状态统一使用：

`registered → data_checked → implemented → single_tested → combination_tested → validated → frozen → submitted`

不满足要求的候选进入 `rejected`，并记录原因，不删除失败记录。

`data_checked` 只表示来源表、必要字段、可用时点和已知异常处理已经核验，不表示方向有效。依赖其他候选的交互或模型型候选，在所有输入组件完成正式单因子检验前不得进入实现。

## 6. 第二阶段：候选实现与接口验收

候选源码和评价规则在本机编辑；真实数据查询、字段与接口验收必须在网页 AIStudio 完成，固定研究面板下载后由本机 `conda quant` 生成可复现的评价结论。

### 操作步骤

1. 只实现登记过的候选。
2. 将数据读取、特征计算和结果输出分离。
3. 同一一级类别共享一次真实取数与数据族验收，不为每个因子重复下载和核验相同原始数据。
4. 在网页 AIStudio 先运行短日期、小股票池版本。
5. 每个候选只做输出级轻检：列严格为 `date、instrument、factor`、股票日期无重复、交易日完整、覆盖率和唯一值充分、因子值有限。
6. 每个候选修改未来输入，确认过去因子完全不变。
7. 分钟、停牌、午休、跨日、盘口空档和财务 PIT 等异常只在相应数据族做一次完整回归；候选若引入新的处理逻辑，再补候选级专项回归。

### 通过条件

- 无重复股票日期；
- 无缺失交易日；
- 每日缺失率低于比赛上限，内部目标覆盖率不低于 95%；
- 因子值为有限数；
- 因子具有有效截面差异；
- 防泄漏测试通过；
- 运行过程可复现。

接口通过只代表因子可以计算，不代表因子有效。

## 7. 第三阶段：单因子评价

“单因子”既包括基础组件，也包括一个完整候选。

本阶段使用 AIStudio 生成并经官方 UI 下载的真实日频研究面板，在本机 `conda quant` 环境执行。候选池、评价代码、门槛和结果文件全部版本化；AIStudio Notebook 只保留数据聚合入口。

### 7.1 技术冒烟与正式评价

2022 短区间只检查覆盖率、缺失结构、截面唯一值、极端值、更新频率、接口和防泄漏。技术合同失败可以停止候选；IC、分组收益或某个季度方向不佳不能据此停止多年评价，也不能事后翻转方向。

正式有效性结论必须覆盖多个年度和市场状态：

- `PV、FR` 的日频或事件数据成本较低，基础候选直接使用完整 2019—2022 研究区间；
- `HF、OB` 的分钟数据成本较高，首轮固定使用 2019—2023 每年 2、8 月的 10 个必跑月份；2019—2022 为开发，2023 两个月只作冻结后的样本外确认；
- 5、11 月为预先声明的备选池，最多启用 6 个月；只能按市场状态覆盖缺口选择，不能按候选表现选择；
- `HF、OB` 在代表月份出现可重复信息后，再补完整年度；代表月份列表必须在查看结果前冻结；
- 同族数据按年或按预先固定分区保存 Parquet，复用日频原始组件；已有列足够时新增候选的 AIStudio 查询次数必须为 0。

### 7.2 预测能力

按交易日计算截面 Rank IC，并汇总：

- Rank IC 均值、标准差、IC_IR、正向胜率和显著性；
- 一期及多期衰减；
- 五分组或十分组收益及单调性；
- 多空收益、夏普和回撤。

### 7.3 分组收益单调性

因子默认方向为数值越大、预期收益越高，因此不能只看最高组减最低组。必须检查：

- 各组平均收益是否随因子组别总体递增；
- 组别序号与组平均收益的 Spearman 相关系数；
- 相邻组收益倒序的次数和比例；
- 最高组、中间组和最低组的排序关系；
- 多空收益是否由单一极端组驱动；
- 单调性在开发期、选择期和冻结期是否稳定；
- 单调性在年度、市场状态及风险中性化前后是否稳定。

不要求每个相邻组在每个区间都严格递增，但总体排序必须有统计稳定性。若原始关系呈 U 型、倒 U 型或明显阈值型，不应直接作为一个有方向的线性因子提交；应先转化为方向明确的候选，或由严格样本外验证的模型形成最终预测值。

### 7.4 稳健性、流动性与可交易性

分别评价年度、涨跌市场、波动状态、行业、市值、流动性和不同收益标签。至少同时报告：

- 各年度和预先定义市场状态的 IC、分组收益及方向一致性，不能用全期平均掩盖单年失效；
- 全股票池，以及按流通市值、成交额和换手率分组的结果；
- 剔除微盘和极低流动性股票后的结果，判断信号是否只是微盘或流动性暴露；
- 停牌、涨跌停、无有效报价等不可交易样本的覆盖和处理；
- 使用下一交易日可执行标签后的换手率、成本敏感性和容量代理；
- 行业、市值和流动性中性化前后的结果。

若预测能力主要来自最低流动性或最小市值组，且在可交易样本或成本后消失，不得认定为可提交的有效因子；可以降级为风险或状态变量。

### 7.5 风险处理

按照接近官方的口径依次去极值、截面标准化、对风险暴露回归取残差，并在残差因子上重新计算全部指标。同时保存处理前和处理后的结果。

### 7.6 单因子结论

单因子评价不直接决定删除组件，而是确定其角色：独立预测信号、条件变量、过滤变量、风险控制变量、分散变量或无有效信息。

## 8. 第四阶段：组合评价

组合前必须明确每个组件的角色和组合理由，不允许只因公式空间存在就加入。

本阶段在本机 `conda quant` 环境执行，使用本地版本化组合规则；需要的新原始组件才返回 AIStudio 按数据族补列。

### 8.1 组合顺序

1. 建立最简单的单组件基准。
2. 每次只加入一个新组件。
3. 记录加入前后的全部样本外指标。
4. 对完整组合逐项删除组件。
5. 比较简单组合和复杂组合。
6. 只有稳定提供增量的组件才能保留。

### 8.2 增量指标

每次组合至少比较：

- Rank IC 均值、IC_IR 和 IC 胜率变化；
- 分组收益单调性变化；
- 多空夏普、最大回撤和换手率变化；
- 与基础因子库相关性变化；
- Elastic Net 非零权重窗口比例和 ModelScore 变化；
- 不同市场状态下的变化。

### 8.3 条件变量评价

条件变量自身 IC 较低不构成淘汰理由。必须检查主信号在不同条件状态下是否存在稳定差异，加入条件后样本外指标是否改善，改善是否跨年度存在，以及删除条件后表现是否稳定下降。

### 8.4 分散组合评价

多个弱信号组合时检查各信号方向、两两相关性、组合后的 IC 波动、收益集中度、权重稳定性，以及样本外是否优于简单基准。

## 9. 第五阶段：机器学习组合

机器学习用于特征组合和条件关系识别，不替代历史验证。

模型研究和训练优先在本机 `conda quant` 上使用固定日频 Parquet 执行；AIStudio 负责数据生成、资源兼容性和冻结后提交链路复现。模型配置、随机种子、特征列表和评价结果必须在本地版本化。

### 操作步骤

1. 只使用已完成时点检查的特征。
2. 建立简单线性或正则化模型作为基准。
3. 只在 2019—2022 内部做滚动训练和验证。
4. 在读取 2023 前冻结特征、参数和模型结构；2023 只确认，不再选择。
5. 固定随机种子、预处理和训练流程。
6. 冻结模型后运行 2024。
7. 将模型预测值作为日频因子进入统一单因子评价。
8. 与简单基准做消融和增量比较。
9. 检查模型训练时间、推理时间和内存。
10. 确认私榜运行不依赖外部网络、本地文件或硬编码日期。

### 准入条件

- 日期切分，不使用随机股票行切分；
- 无目标泄漏；
- 样本外稳定优于简单基准；
- 提升不是由少数日期或股票驱动；
- 模型复杂度与增量收益匹配；
- 完整 Notebook 运行不超过 3 小时。

流程验收与模型准入必须分开：模型成功训练、预测和进入统一评价接口，只说明机器学习工程链路可运行；如果样本外不优于简单基准，则保留结果并回退到简单组合，不得为了使用机器学习而提交模型输出。

## 10. 第六阶段：全局增量评价

本阶段先在本机 `conda quant` 使用下载的候选面板和基础因子面板执行代理评价；冻结候选再在 AIStudio 复现平台兼容结果。若公开基础因子不可按协议下载，则只在 AIStudio 执行该部分，并保存固定配置和输出摘要。

按照官方披露的代理流程，将候选和公开基础因子库共同放入滚动 Elastic Net：

- 训练窗口 60 个交易日；
- 步长 20 个交易日；
- 目标为下一期收益的截面标准化值；
- 保存每个窗口的权重；
- 计算非零权重比例和权重稳定性；
- 计算候选与基础因子库的 Rank 相关矩阵。

此阶段用于评价候选在全场因子环境中的独立贡献，不能只看候选自身 IC。

## 11. 第七阶段：冻结与公榜提交

### 提交准入

候选同时满足以下条件才可进入提交队列：

- Elastic Net 中具有稳定增量；
- 计算时间符合平台限制；

为首次验证比赛上传、后台运行和评分接口，可以建立一次明确标记的“平台链路冒烟提交”。它必须通过数据契约、防泄漏、短窗真实运行和三小时资源预估，但可以不满足显著性、单调性或成本门槛。冒烟提交不得写成正式有效因子，不参与后续参数反推；严格候选仍执行上述全部准入条件。

- 公榜截止前最多选择两个候选进入私榜；
- 两个私榜候选应具有不同信息来源或机制，并保持较低相关性。

### 时间与样本

备选池为 2019—2023 每年 5、11 月，最多启用 6 个月。启用前必须先用与候选收益无关的市场收益、波动和流动性状态检查证明必跑集合存在覆盖缺口，并把选择理由写入冻结记录；不得查看某候选在哪个月表现好再补该月。本地已经存在的 2019—2022 年 8 个备选月默认不参与首轮评价，2023 年备选月暂不查询。

### 标签、预处理与分层

- 主标签为下一中国交易日的 `next_close / next_pre_close - 1`；敏感性标签为 `ret_next_open_to_close` 和 `ret_close_to_next_open`。
- 停牌导致标签缺失，不向后跳到复牌日。
- 同时保存原始方向、每日 1%/99% 去极值后标准化、以及行业、`SIZE、LIQUIDTY` 中性化残差三套结果。
- 同时报告全池、流通市值三分位、流动性三分位，以及剔除市值和流动性最低 20% 的较可交易子集。
- 固定检查 0、10、20、30 bps 单边成本。

### 角色判定

技术门槛为覆盖率不低于 95%、每日有效截面值不少于 50、至少 40 个有标签交易日且防泄漏差异为 0。

“独立预测信号”在主标签登记方向上必须同时满足：

- 全开发期 Rank IC 为正且 t 值不低于 2；
- `PV、FR` 至少 3/4 个开发年度为正；`HF、OB` 至少 60% 的开发期实际评价月份（必跑月加已冻结启用月）为正，且 2023 样本外单独报告；
- 五分组单调性不低于 0.50；
- 中性化后和较可交易子集中方向仍为正；
- 20 bps 成本情景下多空结果不为负。

未达到独立信号门槛时，仍可按证据登记为条件/过滤变量、分散变量或风险变量；方向、分层、状态和增量均不稳定时登记为无有效信息。候选方向不允许原地翻转，相反机制必须使用新编号和未查看区间。
