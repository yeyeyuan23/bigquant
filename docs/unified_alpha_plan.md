# Unified Alpha Plan

> **状态（2026-08-20）**：本计划的 M 专家线已完成——分钟 store 建成、扩窗训练完成并
> 作为正式提交进入决赛（公榜 0.9548 / 私榜 0.8874，checkpoint `252c39ba…`）。当前数据路径、
> 工作区与提交包见根 README；决赛复盘实验见 `experiments/finals_pre/`。
> 下文保持 8 月初计划时点的原文，作为协议与边界的定义文档继续有效。

这份文件是当前架构、数据边界、训练协议和晋级标准的唯一计划文档。旧的
S/I/T、screened15、Bar156、All618 和宽泛 ML Framework 文档已经退出当前路线。

## 1. 目标与输出

目标不是让某一个模型吞下所有信息，而是把不同时间粒度的信息交给三个独立专家，
再只保留能够提高严格样本外 Competition Score 的路线。

所有专家必须输出同一合同：

```text
date, instrument, factor
```

`factor` 是某日某只股票的样本外预测分数；值越高，表示模型对该股票下一交易日
横截面收益排序的预测越高。它不是收益率、仓位或概率。

## 2. 数据边界

- 因子工程输入只来自比赛允许的 `bar1m` 和 `financial`；股票池只用于确定日股键。
- 当前统一因子面板固定为 Candidate454，不存在 Bar156 或 All618。
- 本地训练数据覆盖 2019—2024；任何日期的标签和特征必须严格按可见时点对齐。
- 验证/测试数据只在 `start_date` 前提供有限历史缓冲。按正式半年上限设计，不能假设
  验证时能读取 2019 年以来的完整历史。
- Transformer 单样本窗口固定为 60 个交易日，不再扩大。候选因子自身的最大预热与
  60 日序列合计必须能落在半年缓冲内。
- 分钟数据必须按时间确定性排序；日内收益不得跨午休连接；计算完成后裁回
  `[start_date, end_date]`。
- 平台输出必须非空、日期有界、日股键唯一、数值有限且每日横截面非常数。

## 3. 因子池是特征工程

Candidate454 是对量价、微观结构与财务信息做过降噪、归一和经济机制表达后的日频
特征面板。它用于 T 和 X 专家，但不替代原始分钟序列：日频聚合会丢失冲击先后、
持续时间、恢复路径和盘口形状迁移，因此 M 专家必须保留原始日内信息。

## 4. 三专家

### T：Factor Temporal

```text
Candidate454 × 过去60日
→ 缺失 Mask 与日截面标准化
→ 特征投影
→ 多尺度因果 CNN
→ Transformer
→ 时间汇总
→ DeepSets 横截面上下文
→ 每股 OOS 分数
```

时间窗口固定为 60 日。`temporal_base` 和 `temporal_deep` 只是同一专家的容量候选，
必须按严格 OOS `J_stable` 选胜者；除非二者低相关且组合产生正 `delta_J`，否则不能
同时进入最终融合。

### X：Factor Cross-sectional

输入为当日 Candidate454。LightGBM 是主模型，MLP 是挑战模型。二者比较相同日期、
股票池、标签和 OOS 窗口，先选出一条 X 路线；只有可验证的正增量才允许内部组合。

### M：Raw Microstructure

输入为当日原始分钟价格、成交和盘口序列。代码固定使用前三档盘口，使本地压缩数据与
平台 `bar1m` 能生成同一个 canonical schema。任何 instrument 映射和价格/成交单位修复
必须在入库时显式完成，模型不会猜字段或倍率。本地 E2E profile 的已证实规则是：
`instrument_id` 通过一一对应表转换为正式代码，价格与成交额除以 100，成交量、盘口量和
成交笔数不缩放；平台 canonical profile 不做这些转换。第一版使用双通路：

1. 多尺度 TCN/CNN 编码分钟顺序、冲击、持续与恢复；
2. 小型 MLP 编码尾盘、深度、价差、microprice 和冲击反转等显式统计。

两路合并后加入当日横截面上下文并输出日频分数。第一版不使用大型分钟
Transformer；它只能在 TCN/CNN 基线通过后作为挑战模型。

每个样本是 `某日 × 某股 × 最多242分钟 × 17通道`。17 个通道覆盖 session-safe
分钟收益、K 线位置、相对价差、microprice、L1/L3 深度不平衡、盘口形状、成交活跃度、
单笔成交尺度和日内时钟。上午与下午第一分钟的收益均为空，禁止跨午休连接。网络的
序列通路使用缺失 mask 和多尺度因果 TCN；统计通路使用全日均值、波动、最新值、尾盘
均值和通道覆盖率。两路融合后才加入 DeepSets 横截面上下文。

M 的训练器与基线共用 `60日训练 / 隔离1日标签 / 20日预测` 滚动块。数据 store 不存在
时统一套件必须明确 `skipped`，不得生成全零文件冒充模型输出。

store manifest 必须记录每个源文件和映射表的 SHA-256，以及映射覆盖、重复键、OHLC 合法率、
有效最优盘口率、跨价盘口、`mid/close` 单位比和分钟数范围。缺失映射、非一一对应映射、
价与盘口单位不一致或单股日内超过 242 行必须在训练前硬失败。M 训练器只接受该审计版
schema v2。

## 5. 当前 J 基线

统一路线的比较基线固定为：

```text
Candidate454 全因子池
→ 每日横截面预处理
→ Elastic Net
→ 60个交易日训练 / 20个交易日预测
→ candidate454_elasticnet_full_oos.parquet
```

这是 `baseline route`，用于回答新专家相对完整因子池线性组合是否有增量。它与本地
Competition Score 中用于近似平台拥挤环境的 `reference factor pool` 不是同一个
概念，代码和报告中必须分开命名。

每条专家路线都必须报告：

- 单独的年度 J、`J_mean`、`J_worst`、`J_std`、`J_stable`；
- `J(expert blend) - J(elasticnet baseline)`；
- 与 Elastic Net 基线及其他专家的日截面相关性；
- 覆盖行数、缺失填充数和全部 OOS 日期边界。

J 是模型选择和融合的外层评价，不是神经网络或 Elastic Net 的训练损失。

## 6. OOS 协议

- 标签：下一交易日收益的每日横截面排序中心化值。
- 禁止随机拆分股票日。
- 开发训练从 2019 年开始；2023H1、2023H2、2024H1、2024H2 按日期严格滚动 OOS。
- 任何预测行只能由该日期之前可见的特征、标签和冻结参数产生。
- 神经模型以相关性损失加稳健回归项训练；树和线性模型使用同一目标口径。
- 公榜、私榜和本地 J proxy 是不同证据层，不得互相冒充。

“每股一个 OOS 分数”指：对验证日 `d` 的股票 `s`，模型只能使用 `d` 当时可见的
输入以及在 `d` 之前训练好的参数，生成一个标量 `score[d, s]`。当天所有股票的分数
做横截面 rank 后形成最终 `factor`。例如：

```text
2024-07-01, 000001.SZ,  0.74
2024-07-01, 000002.SZ, -0.18
2024-07-01, 000003.SZ,  0.31
```

这里的 0.74 只表示相对排序较高，不表示预期上涨 74%。

## 7. 融合与防拖累

不再默认把所有容量版本等权平均。正式融合顺序为：

1. 先冻结 Candidate454 Elastic Net OOS 基线；
2. T、X、M 各自完成独立训练和 OOS 预测；
3. 每个专家家族先选一条胜者路线；
4. 对基线加单个专家做配对 `delta_J`；
5. 只对通过增量门槛的路线搜索非负、和为 1 的静态权重；
6. 以 `J_stable` 为主，`J_worst`、相关性和覆盖为保护条件；
7. 允许弱专家权重为 0。

静态晚融合是必须先跑通的基线，但动态 MoE 也必须作为挑战路线完成严格对照，不能在
未实验前排除。MoE 门控只能读取预测时可见的市场状态、缺失率、波动、流动性和三个专家
输出；禁止读取当日或未来标签。门控必须用过去已经产生的 OOS 专家预测滚动训练，并在
后续未参与门控拟合的日期评分，不能在同一段 OOS 上同时拟合权重和报告成绩。

第一轮 MoE 只比较小模型：线性 softmax gate 与两层 MLP gate；同时保留静态等权、静态
最优和单专家基线。每种门控至少运行多个 seed，并记录 `J_stable`、`J_worst`、配对
`delta_J`、逐年/逐折表现、专家权重分布、门控塌缩率和权重换手。若 MoE 的提升不能在
未见期和多数 seed 稳定复现，则正式提交仍使用更简单的静态融合。端到端联合重训仍作为
后续挑战，不与第一轮门控混在一起。

## 9. 待优化

这一节记录不会阻塞当前正式实验、但在下一轮数据构建和提交运行时中必须处理的工程项。
当前正在运行的长任务不得为了代码重构而中断；优化必须先在独立输出目录做等价性与性能
基准，再替换正式路径。

### 9.1 当前两个数据构建器的边界

M 分钟仓构建器用 Polars LazyFrame 从 2019—2024 的 72 个月 `bar1m` 文件逐月读取数据，
在单个惰性执行图中完成列裁剪、instrument 一一映射、E2E 固定单位修复、主键与行情质量
审计及 17 个分钟微观结构通道。通道以 `float32 + ZSTD` 按交易日原子写入，并用
`progress.json` 支持输入级断点续跑；源文件 SHA-256 与主计算重叠执行。最终 manifest 记录
schema、通道、日期范围、行数、股票数、源文件和映射表 SHA-256 及质量审计结果。它只
服务于 M 专家，不负责生成 Candidate454。

Candidate454 组装器接收六个已经计算完成的因子块，按年份合并成统一日频面板：

| 因子块 | 数量 |
|---|---:|
| Base | 138 |
| Remaining | 132 |
| GTJA | 149 |
| CICC | 13 |
| PV | 16 |
| Direct | 6 |
| 合计 | 454 |

该组装器使用 DuckDB 完成长表 pivot，并用 Pandas 合并宽表、生成可用性 mask、转换
`float32`，最后按年份写 ZSTD Parquet。它负责组装和验证，不应被描述成从原始分钟数据
现场计算全部 454 个公式。

## 10. Notebook 生成策略

开发 Notebook 与平台提交 Notebook 是两个不同产物。开发 Notebook 可以读取开发机的
Candidate454 和 M store、执行 OOS 实验；提交 Notebook 必须只依赖平台允许的数据和
冻结资产，不能引用开发机路径、训练标签、历史特征仓或研究报告。

### 10.1 训练与提交职责

开发机负责：

1. 使用 2019—2024 数据训练 T、X、M 和基线模型；
2. 生成严格 OOS 路线并按 `J_stable`、`J_worst`、配对 `delta_J` 和相关性选择胜者；
3. 冻结胜者模型的权重、必要的预处理参数和最终融合权重；
4. 导出与模型配置、Candidate454 顺序、数据 schema 和代码提交绑定的版本 manifest。

提交 Notebook 负责：

1. 仅从 `bar1m`、`financial` 和股票池键读取提交期可见数据；
2. 在半年历史上限内现场生成冻结模型所需的当期输入；
3. 加载冻结权重，只做推理，不在平台重新训练、调参或按验证结果选模型；
4. 输出唯一的 `date, instrument, factor` 结果。

如果最终胜者仍使用全部 Candidate454，Notebook 必须计算当期 454 个因子值；“预先训练
权重”不能替代未来日期的特征计算。454 个因子必须共享基础组件和一次原始数据扫描，不能
实现为 454 次独立查询或 454 个逐列 merge。若后续通过剪枝或蒸馏减少输入维度，必须重新
训练/微调并重新完成全套 OOS 与前缀验证，不能只在提交代码里擅自删列。

### 10.2 平台流式运行路径

```text
start_date 前半年至 end_date 的 bar1m + financial
        ↓
按 5—10 个交易日分块读取
        ↓
一次 canonicalization、单位审计和共享基础组件计算
        ├─ Candidate454 float32 日频矩阵
        │      ├─ 最近60日环形缓冲 → T
        │      └─ 当日截面 → LightGBM / MLP
        └─ 17通道分钟块 → M
        ↓
冻结专家与冻结融合权重推理
        ↓
横截面 rank 与输出合同检查
        ↓
释放当前原始分钟块和中间变量
```

Candidate454 与 M 必须共享同一次 `bar1m` 扫描。提交运行时不落完整六年或半年分钟仓，
不保留所有原始分钟 DataFrame，也不先复制开发机的 789 MiB Candidate454 特征仓。

### 10.3 内存与超时控制

- [ ] 使用 Polars/Arrow 分块读取，查询列和日期边界必须在源端裁剪；禁止 broad scan。
- [ ] Candidate454、mask 和模型输入统一为 `float32`/紧凑布尔数组；证券键在内部使用
  整数编码，输出时再映射回正式 instrument。
- [ ] T 只保留最近 60 个交易日环形缓冲；X 只保留当前预测块；M 处理完一个分钟块后
  立即释放。
- [ ] 不创建 454 个长期存活的 DataFrame，不逐因子重复合并，不同时保留原始分钟表、
  多份 canonical 表和全部中间通道。
- [ ] 若平台允许临时文件，可用受控的 Arrow IPC/NumPy memmap 作为溢出缓冲；临时目录
  必须限定范围并在 `main()` 结束时清理。
- [ ] 仅打包通过 OOS 门槛的专家；弱专家权重为零时不加载其模型和专属输入路径。
- [ ] 权重包使用最小必要精度和格式。是否使用伴随文件或嵌入 Notebook，必须在确认平台
  文件数量、单文件大小和依赖规则后决定，不能假设开发机路径在平台存在。
- [ ] 任一路径缺失时不得生成全零伪结果；仅允许使用预先定义、通过同样 OOS 验证的冻结
  fallback，并在运行日志中明确记录。

### 10.4 生成物与单一来源

正式提交代码以一个 canonical `.py` 为唯一实现来源。Notebook 由构建脚本机械生成，不能
维护第二份手写模型。每次生成至少产出：

- `submission.py`：包含 `main(datasources, start_date, end_date)` 的可审查源代码；
- `submission.ipynb`：代码必须与 `.py` 完全一致，默认只含说明 cell 和一个代码 cell；
- 冻结权重及 manifest：记录模型类型、参数、特征顺序、schema、训练提交和 SHA-256；
- build report：记录生成时间、依赖、文件大小和所有验证结果。

构建器必须拒绝未冻结的实验目录、候选数不一致、权重缺失、schema 不匹配或仍引用本地
绝对路径的输入。

### 10.5 提交前强制验证

- [ ] 导出 `.py` 并通过 `py_compile`；Notebook 通过 `nbformat` 校验，代码 cell 与 `.py`
  做字节级或规范化后的一致性检查。
- [ ] 静态扫描数据源，只允许 `bar1m`、`financial` 和股票池键；禁止 factorlib、exposure、
  bar5m、标签表和开发机缓存路径。
- [ ] 在真实 AIStudio 数据上运行最小五日预测，同时实际提供半年历史缓冲；记录总耗时、
  各阶段耗时、峰值 RSS、查询行数和输出行数。
- [ ] 用同一输入执行 full/cutoff 前缀检查；公共前缀必须 `different_rows=0`。
- [ ] 输出必须非空、日期有界、键唯一、数值有限且每日横截面非常数；连续两次运行结果
  必须确定性一致。
- [ ] 再执行较长日期窗口，确认耗时和峰值内存相对平台限制保留至少两倍安全余量；未确认

### 10.6 实施顺序

1. 等当前完整 OOS 套件完成，冻结各专家候选结果；
2. 选出 T、X、M 家族候选并完成静态融合细网格、敏感性和独立验证；
3. 在同一 OOS 合同下完成严格滚动 MoE 挑战和多 seed 稳定性审计；
4. 按未见期结果选择静态或 MoE，保存最终最小权重包；
5. 在独立分支实现 Polars 单扫描运行时和 Pandas 金标等价测试；
6. 先生成只覆盖五日预测的 `.py + .ipynb`，在真实 AIStudio 执行；
7. 通过资源、输出和前缀门槛后，再生成最终可提交版本；
8. 平台官方得分返回后，再决定是否进入端到端联合训练、蒸馏或更大模型。
